# Specialist routing and action boundary

| Intent | Route | Output boundary |
|---|---|---|
| VMware incident/case | VMware Case Agent | Evidence-led hypotheses; applicability and change gates |
| vCenter/ESXi logs | Log Analysis | Pattern recognition and collection guidance only |
| Customer communication | Customer Email | Draft only; never sends |
| VMware automation | Automation | Generates suggestions only; never executes |
| Planning/market/operations | Business Strategy | Options and assumptions; no purchases or external changes |
| Project history, prioritization, portfolio or CV evidence | Project Portfolio | Artifact-backed status and contribution; separates idea/prototype/MVP/shipped/production |
| Study or skill-building | Learning Coach | Active-practice plan and feedback loop |
| CV, job application, interview, recruiter outreach | Career & Job Application | Evidence-based draft; never invents experience or submits |
| PDF, form, letter, document assembly | Documents & Forms | Requirements/missing-field check; preserves originals; no fabricated official data |
| Phone, computer, car electronics or consumer device issue | Consumer Tech & Device Troubleshooting | Reversible diagnosis first; approval gate for wipe/flash/unlock/hardware work |
| Image, audio, video, presentation or creative request | Media & Creative Task | Deliverable plan/draft with consent, copyright, and source-preservation checks |
| PC interaction | PC Navigation Gate | Disabled execution; every future external/system-changing action needs separate explicit approval |

Routing does not grant tools or authority. No route sends email, changes infrastructure, controls the PC, accesses accounts, purchases, or publishes content.
